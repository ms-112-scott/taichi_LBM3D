## 已知的重要修正

以下五項是審查過程中找出並已驗證修正的實質錯誤，之前的草稿若有殘留請以此為準：

1. **Poiseuille 測試會假性通過。** `commit a0461be` 同時改了 `tau_f` 與 Guo 力項係數，兩邊的 1/9 剛好抵消，所以 Poiseuille 解析解比對驗不出任何東西。P0.1 已改用**衰減剪切波**（`U(t) = U₀·exp(−νk²t)`），且兩處都必須一起修。
2. **`S_dig` 的結構是 TRT，不是壞掉的 MRT。** `s_other` 只出現在 index **4, 6, 8, 16, 17, 18**（奇矩 q、m），且 `s_other = 8(2−s_v)/(8−s_v)` 使 **Λ = 3/16 恆定**（τ = 1.0 / 0.8 / 0.6 / 0.51 / 0.5003 全部驗得 0.1875）。把它改成 1.0 會破壞這個專案唯一做對的地方。正確的改法是在 P0 把 `M` 換成正交的 d'Humières 基底。
3. **頻寬是 488 B/cell/step，不是 152。** `colission` 42 + `streaming1` 38 + `streaming3` 42 = 122 個 float，三趟完整的陣列來回。所以 A100-40GB 上 900 MLUPS ≈ 439 GB/s ≈ **28%** 使用率。**kernel 融合（488 → 152 B，3.2×）是單一最大的效能改善**，列為 P6.0。
4. **WALE 不能只靠 f^neq。** f^neq 的二階矩只給對稱的 S_ij，WALE 需要完整的速度梯度（含反對稱的渦度部分），必須用有限差分（+30–50% 頻寬）且會破壞 kernel 融合。先做 Smagorinsky。
5. **u_lat 入流維持 0.05，不是 0.10。** 建築轉角/文丘里加速是入流的 1.5–2.5 倍，入流 0.10 會讓局部峰值到 0.15–0.25、Ma 到 0.26–0.43。改為監控 `get_max_v()/0.577`，超過 0.25 就降。收斂步數維持約 19,000（建築）/ 24,000（都市）。

## 現有 repo 已確認的三個錯誤

寫在 06 的第 12 節，這裡重列最該先修的三個：

- `2phase/lbm_solver_3d_2phase.py:605` — 運算子優先序：`psi = rho_r - rho_b/(rho_r+rho_b)`，缺括號。
- `Solute_Solver.py:344,360` — 條件寫成 `==1` 應為 `==2`，Z 方向的絕熱溶質邊界條件實際上沒有作用。
- `lbm_solver_3d_cavity.py:89` — 連續三次檢查 `abs(fx)`，應為 fx / fy / fz。
